# /sub-supplier-evaluation

> 고객 요구사항 배경은 [HKMC-FACTS.md](../../HKMC-FACTS.md) 4·5장을 참고한다.
> 낯선 자리표시자나 연결된 도구는 [CONNECTORS.md](../../CONNECTORS.md)에서 확인한다.

현대·기아 공급망에서 고객 요구사항은 하위 공급망 전체로 전달되어야 한다. 이 스킬은 우리 회사가 하위 협력사를 같은 기준으로 관리하도록 돕는다.

## 시작 질문

1. 목적: 신규 선정 / 정기 평가 / 문제 업체 특별 점검
2. 회사 평가 기준서(항목·배점·등급 기준)가 있는가 — 있으면 그것만 쓴다
3. 업체 정보: 공급 품목, 거래 기간, 실적 데이터(납입 불량, 납기, 클레임)
4. 업체 보유 인증(IATF 16949, ISO 9001, SQ 인증 등)

## 평가 틀 (회사 기준서가 없을 때 제안용)

| 영역 | 평가 근거 |
|---|---|
| 품질 실적 | 수입검사 불량률, 공정 유출 불량, 클레임 건수, 대책서 제출·이행 |
| 납입 실적 | 납기 준수율, 결품, 긴급 대응 |
| 품질 체계 | 인증 보유, 변경점 관리, 부적합품 관리, 계측기 관리, 로트 추적 |
| 기술·개발 | 개발 일정 대응, 공법 역량 |
| 원가 | 단가 경쟁력, 원가절감 협력 |
| 경영·ESG | 재무 안정성, 행동규범 준수 확인, 안전·환경 법규 준수 |

배점은 회사가 정하도록 비워 두고 예시 비율만 제안한다. 등급 기준(예: A/B/C/D)과 등급별 조치(유지 / 개선 요구 / 거래 축소 검토)도 회사 결정 사항으로 둔다.

## 작업

1. 실적 데이터로 정량 항목을 계산한다(코드로 실행)
2. 현장 점검이 필요하면 체크리스트를 만든다 (`supplier-quality`의 `/process-audit` 형식 응용)
3. 결과표와 미흡 항목 개선 요구서(지적 내용, 요구 조치, 회신 기한)를 만든다
4. 신규 선정이면 후보 업체 비교표와 추천 이유

## 출력 형식

```markdown
## 협력사 평가: [업체명] — [목적] [기간]
| 영역 | 항목 | 실적/근거 | 점수 | 비고 |
### 종합 판정 (회사 기준) 
### 개선 요구 사항
| 지적 | 요구 조치 | 회신 기한 |
```

## 주의

- 평가 결과로 거래 중단 같은 결정을 단정하지 않는다. 판단 근거와 선택지를 제시하고 결정은 담당자가 한다.
- 하도급 거래 관련 법규(하도급법 등)상 부당한 요구가 되지 않도록, 원가·기술 자료 요구는 회사 법무·구매 규정을 따르라고 적는다.
