# /work-standard

> 낯선 자리표시자나 연결된 도구는 [CONNECTORS.md](../../CONNECTORS.md)에서 확인한다.

현장 작업자가 **한 장으로 보고 그대로 따라 할 수 있는** 작업표준서를 만든다.

## 받을 정보

- 공정명, 품번(군), 설비·지그·공구
- 작업 순서(말로 설명, 동영상 메모, 사진 설명 모두 가능)
- 관리계획서의 해당 공정 행(특성·규격·검사 방법) — 있으면 반드시 맞춘다
- 회사 양식(있으면 그 칸 그대로)
- 다국어가 필요하면 대상 언어

## 작성 원칙

- 한 단계에 한 동작. 동사로 시작한다 ("커넥터를 지그에 끼운다")
- **핵심 포인트와 이유**를 단계마다 붙인다. 이유가 있어야 작업자가 지킨다
- 품질 포인트(특별특성은 기호 표시), 안전 포인트(보호구, 끼임·베임 위험)를 구분한다
- 수치(토크, 설정값, 치수)는 관리계획서·도면 값만 쓴다. 모르면 `[값 확인 필요]`
- 이상 발생 시 행동: 멈춘다 → 표시한다 → 반장에게 알린다처럼 구체적으로
- 표준 시간(ST)이 주어지면 단계별로 적는다

## 출력 형식

```markdown
# 작업표준서
| 문서번호 | | 개정 | | 시행일 | |
| 공정명 | | 품번 | | 설비/지그 | |
| 작성 | | 검토 | | 승인 | |

## 작업 순서
| 순서 | 작업 내용 | 핵심 포인트 | 이유 | 품질/안전 | 시간(초) |
|---|---|---|---|---|---|

## 검사 항목 (관리계획서 연계)
| 특성 | 기호 | 규격 | 방법 | 빈도 |

## 이상 발생 시 조치
## 개정 이력
| 개정 | 일자 | 내용 | 작성 |
```

## 다국어 병기

- 한국어 원문 아래에 대상 언어를 줄마다 병기한다. 전문 용어는 회사 용어집이 있으면 그것을 쓴다
- 번역 후 "현지 관리자 검토 필요" 표시를 넣는다. 안전 문구는 특히 현지 확인을 권한다
- 숫자·단위·기호는 번역하지 않는다

## 개정 모드

기존 작업표준서와 변경 사유(4M 변경, 클레임 대책, 설계변경)를 받으면 바뀐 줄만 표시하고 개정 이력을 추가한다. 관련 PFMEA·관리계획서 개정이 함께 필요한지 알려 준다.

## 연결 도구가 있으면

- **~~document storage**: 최신 관리계획서와 기존 작업표준서를 찾아 대조한다.
- **~~groupware**: 개정본 결재 기안을 만든다.
