# /drawing-review

> 낯선 자리표시자나 연결된 도구는 [CONNECTORS.md](../../CONNECTORS.md)에서 확인한다.

## 보안 확인

고객 도면은 기밀 자료다. 첨부 전에 회사 정보보안 규정이 AI 도구 사용을 허용하는지 확인했는지 한 줄로 묻는다. 사용자가 이미 확인했다고 하면 다시 묻지 않는다.

## 검토 항목

도면·사양서를 끝까지 읽고 아래를 표로 뽑는다. 이미지 도면이면 보이는 범위에서 읽고, 읽을 수 없는 부분은 "판독 불가"로 남긴다.

1. **기본 정보**: 품번, 품명, 개정번호·개정 이력, 적용 차종
2. **특별특성**: 안전·법규·기능 중요 특성 기호와 해당 치수·특성. 기호 정의가 도면에 없으면 고객 규격 확인 항목으로 둔다
3. **치수·공차**: 사내 공정으로 맞출 수 있는지 의심되는 공차, 측정 방법이 정해지지 않은 치수
4. **재질·구매 부품**: 지정 재질, 지정 부품(단자·커넥터·튜브·클립 등) 품번, 대체 허용 여부
5. **참조 규격**: 도면에 적힌 고객 규격·국제 규격 번호 목록 — 사내 보유 여부를 확인 항목으로 둔다
6. **시험·검사 요구**: 시험 항목, 조건, 판정 기준, 시험 주기
7. **표기·라벨·포장**: 라벨 내용, 식별 표시, 포장 사양
8. **모순·누락**: 도면과 사양서가 서로 다른 값, 단위 누락, 개정 이력과 본문 불일치

## 출력 형식

```markdown
## 도면 검토: [품번] Rev.[ ]
### 1. 요약 — 즉시 질의 필요 [n]건, 사내 검토 필요 [n]건
### 2. 특별특성 목록
| No | 특성 | 기호 | 규격 | 관리 방안(초안) |
### 3. 제조 타당성 우려
| 항목 | 내용 | 우려 | 제안 |
### 4. 참조 규격 확인
| 규격 번호 | 내용 | 사내 보유 |
### 5. 고객 질의서 (Q&A 시트)
| No | 도면 위치 | 질의 | 제안 답 |
```

질의서는 고객에게 그대로 보낼 수 있게 정중하고 짧은 문장으로 쓴다.

## 주의

- 도면에 없는 규격값을 추정해 넣지 않는다.
- 규격 원문(고객 규격서)이 없으면 "규격 미보유 — 고객 요청 필요"로 둔다.
