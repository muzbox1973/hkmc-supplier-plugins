# /approval-draft

> 낯선 자리표시자나 연결된 도구는 [CONNECTORS.md](../../CONNECTORS.md)에서 확인한다.

## 받을 정보

- 기안 종류(품의 / 보고 / 시행 / 협조), 결재 라인(있으면)
- 핵심 내용과 숫자(금액, 수량, 일정)
- 회사 기안 양식이나 이전 기안 예시 — 있으면 그 문체·항목을 그대로 따른다

## 작성 원칙

- **제목**: 무엇을 어떻게 하겠다는 것인지 한 줄 ("○○ 라인 압착기 2대 교체 투자 품의")
- **첫 문단 = 결론**: 승인 요청 사항, 금액, 일정을 먼저 쓴다
- 본문은 번호 목록(1. 2. 3. / 가. 나. 다.)으로 짧게 쓴다
- 숫자는 단위와 기준일을 붙인다. 계산이 있으면 코드로 검산한다
- 대안 비교가 필요한 품의는 2~3개 안을 표로 비교하고 추천안과 이유를 적는다
- 끝에 "붙임" 목록을 적는다. 첨부 파일이 실제로 있는지 사용자에게 확인한다

## 기본 형식

```
제목: 

1. 목적
2. 현황 (문제·배경, 숫자 근거)
3. 검토 내용 (대안 비교, 효과, 위험)
4. 요청 사항 (승인 내용, 금액, 일정, 담당)
5. 향후 계획

붙임  1. ○○○ 1부.
      2. ○○○ 1부.  끝.
```

공문(시행문) 형식이 필요하면 수신·참조·제목·본문·붙임·끝 표기를 행정 공문 관례대로 쓴다.

## 연결 도구가 있으면

- **~~groupware**: 결재 양식을 불러와 칸에 맞춰 채우고, 상신 전 사용자 확인을 받는다. 상신은 사용자가 직접 한다.
