# /process-audit

> 낯선 자리표시자나 연결된 도구는 [CONNECTORS.md](../../CONNECTORS.md)에서 확인한다.
> 고객 특정 요구사항(CSR) 예시는 [HKMC-FACTS.md](../../HKMC-FACTS.md) 4장을 참고한다.

## 모드 1: 체크리스트 만들기

대상 라인·공정과 감사 계층(작업자 / 반장·조장 / 팀장 / 공장장)을 묻는다. 계층이 높을수록 항목 수를 줄이고 시스템 항목 비중을 높인다.

기본 항목 묶음 (공정에 맞게 고른다):
- **셋업 검증**: 초물 검사 기록, 재료 교체·공구(금형·애플리케이터) 교체·정지 후 재가동 시 조건 확인
- **작업 표준 준수**: 게시된 작업표준서가 최신판인가, 작업자가 그대로 하는가
- **공정 조건**: 설비 설정값이 관리계획서 범위 안인가, 기록이 있는가
- **검사**: 순회검사 주기 준수, 한도 견본 상태, 계측기 교정 라벨
- **부적합품 관리**: 불량품 식별·격리 구역, 재작업 기록
- **식별·추적**: LOT 라벨, 선입선출, 혼입 방지
- **오류방지 장치**: 일일 작동 점검 기록
- **3정5S·안전**: 통로, 보호구, 설비 안전장치

각 항목은 "예/아니오"로 판정할 수 있는 문장으로 쓴다. (나쁜 예: "작업표준 관리 상태" / 좋은 예: "게시된 작업표준서 개정번호가 문서대장의 최신 개정번호와 같다")

## 모드 2: 결과 정리

감사 메모·사진 설명을 받으면:
1. 지적사항을 항목별로 분류하고 등급(중대 / 일반 / 관찰)을 제안한다. 등급 기준이 회사에 있으면 그 기준을 쓴다.
2. 지적사항마다 즉시 조치와 근본 대책, 담당, 기한을 표로 만든다.
3. 반복 지적(이전 감사와 같은 항목)을 따로 표시한다.

## 출력 형식

```markdown
## 공정감사 [체크리스트 / 결과 보고]: [라인] [날짜]
**감사 계층:** | **감사자:** | **대상 공정:**

| No | 항목 | 판정(O/X) | 지적 내용 | 등급 | 조치 | 담당 | 기한 |
|---|---|---|---|---|---|---|---|

### 요약: 적합률 [x/y], 중대 [n], 반복 지적 [n]
```

체크리스트는 현장에서 출력해 쓰기 좋게 Excel 또는 A4 한 장 분량으로 만들 수 있다고 제안한다.

## 연결 도구가 있으면

- **~~document storage**: 최신 작업표준서·관리계획서 개정번호를 대조한다.
- **~~groupware**: 결과 보고서를 결재 기안문으로 바꾼다.
