# /claim-response

> 낯선 자리표시자나 연결된 도구는 [CONNECTORS.md](../../CONNECTORS.md)에서 확인한다.

클레임 초기에는 **고객 라인이 멈추지 않게 하는 것**과 **불량이 더 나가지 않게 막는 것**이 원인 분석보다 먼저다.

## 1단계: 상황 정리 (첫 응답에서 바로)

통보 내용에서 다음을 뽑아 표로 정리하고, 빠진 정보는 고객에게 물을 질문 목록으로 만든다.
- 고객사·공장·라인, 품번, 불량 현상, 발견 수량과 사진 유무
- 발견 시점(조립 중 / 출하검사 / 필드), 해당 LOT 또는 납품일
- 고객 요구사항(선별 인원 파견, 대체품, 회신 기한)

## 2단계: 영향 범위 산정

의심 범위를 아래 순서로 계산하는 표를 만든다. 수량은 사용자가 준 재고 데이터로만 채운다.

| 위치 | 의심 LOT | 수량 | 조치 |
|---|---|---|---|
| 고객 라인·창고 | | | 현장 선별 / 반송 |
| 운송 중 | | | 도착 즉시 격리 |
| 사내 완제품 창고 | | | 출하 보류·선별 |
| 사내 재공품 | | | 공정 보류 |
| 원자재·부품 | | | 수입품 보류(자재 원인 의심 시) |

## 3단계: 초동 조치 계획

- 선별 기준과 방법(전수 / 샘플), 판정 한도 견본
- 선별 인원·시간 계획, 양품 식별 표시(선별 완료 라벨, 클린 포인트)
- 대체품 긴급 생산·납품 계획
- 불량품(구품) 회수·보관 방법: 고객 요구 시 분석용 실물 확보, 사진·로트 라벨 보존
- 불량 재현이 안 되는 NTF 건은 분석 절차(재현 조건, 계측 기록)를 따로 남긴다

## 4단계: 커뮤니케이션 초안

1. **고객 회신 메일**: 접수 확인 → 즉시 조치(보류·선별·대체품) → 다음 회신 시점 약속. 원인을 추정으로 단정하지 않는다.
2. **내부 긴급 보고**: 현황, 영향 수량, 조치, 필요 지원(인원·차량·특근), 의사결정 필요 사항.
3. **현장 지시문**: 보류 대상과 표시 방법, 선별 기준, 기록 양식.

## 출력 형식

```markdown
## 클레임 초동 대응: [고객사] [품번] [현상]
**접수:** [일시] | **회신 기한:** [일시] | **위험도:** [라인정지 위험 상/중/하]

### 1. 확인된 사실 / 확인 필요
### 2. 영향 범위
### 3. 초동 조치 (담당·완료 시각)
### 4. 고객 회신 메일 초안
### 5. 내부 보고 초안
### 6. 다음 단계: 8D 착수 (/eight-d-report)
```

## 연결 도구가 있으면

- **~~MES / ~~ERP**: LOT별 생산·출하·재고 수량을 조회해 영향 범위를 채운다.
- **~~email**: 회신 메일을 초안으로 만든다(발송은 사용자 확인 후).
- **~~chat**: 현장 지시문을 생산·물류 채널에 올릴 수 있게 정리한다.

## 주의

- 클레임 비용 부담(구상) 금액이나 귀책 판단은 계약과 고객 기준에 따라 다르므로 단정하지 않고 "협의 필요"로 둔다.
- 초동 단계가 끝나면 `/eight-d-report`로 넘어가도록 안내한다.
